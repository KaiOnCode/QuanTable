# 笔记：Agent 架构缺陷诊断——为何感觉“不够智能”？

## 1. 核心结论
> **是架构有明显欠缺，但不是“结构”问题。**

我们的 **ReAct Loop 核心骨架是正确的**（与 Claude Code 同源）。真正缺失的是附着在骨架上的 **“智慧层”**（规划、记忆、校验）。目前 Agent 像“有腿无脑”，能跑但总撞墙。

## 3. 三个最致命的缺失（优先级最高）

### 🚨 缺失一：Plan-before-execute（缺乏规划）
- **现状**：Agent 看到用户请求后，**直接调工具**。导致频繁调用无用工具或顺序错乱。
- **Claude Code 做法**：执行前先思考“我需要什么数据？按什么顺序获取？”，生成一个隐式或显式的执行计划。
- **影响**：DeepSeek 本身缺乏规划能力，我们必须**在架构层强制加一个 Planning Step**。
- **预期收益**：显著减少无效工具调用和逻辑跳跃。

### 🚨 缺失二：记忆自动注入（失忆症）
- **现状**：`MemoryStore` 代码已写完（包含 OWM 评分、FTS5 索引），但 **从未被接入 ReAct 循环的 System Prompt**。
- **Claude Code 做法**：每一轮对话自动检索相关记忆并注入上下文。
- **影响**：Agent 是“金鱼脑”，刚分析完 AAPL 的 PE，下一轮就忘光，导致重复查数据。
- **预期收益**：让 Agent 拥有长期工作记忆，避免重复劳动。

### 🚨 缺失三：输出校验（防幻觉）
- **现状**：LLM 可能编造股票价格、虚构新闻标题，我们**没有任何校验机制**。
- **Claude Code 做法**：在多个层面（语法、事实逻辑、格式）校验输出。
- **影响**：生成的报告看似合理，实则数据错误，毫无可信度。

---

## 4. 重要提醒：这不是架构问题

> **ReAct 循环是正确的。** 
> 5-phase 迭代、流式执行、上下文压缩都与顶级 Agent 对齐。

如果把 Agent 比作汽车：
- **结构（底盘/引擎）** = ReAct Loop（**没问题**）
- **缺失的“智慧层”** = 导航仪（规划）、行车记录仪（记忆）、质检员（校验）

---

## 5. 行动建议（非侵入式修复）

这三个致命缺失**不需要重写现有代码**，只需新增功能模块挂载到核心循环上：

1. **增加 Planning Hook**：在 `_query_loop` 最前方插入一个 `_plan_step()`，强制 LLM 输出 JSON 计划后再执行工具。
2. **接入记忆系统**：在构建 System Prompt 时，调用 `MemoryStore.retrieve()` 注入上下文（仅需改动 1-2 处）。
3. **增加事实校验**：引入 `FactChecker` 模块，对关键数据（价格、市值）做二次确认或逻辑自洽校验。

**预测效果**：补齐这三个模块后，Agent 的“笨拙感”会有质的改善（不再乱调工具、不再健忘、不再编造数据）。
